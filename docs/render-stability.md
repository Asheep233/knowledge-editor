# 渲染与往返稳定性（产品级不变量）

> 主理人 2026-10-09 明确要求：**「文档应该有随更新渲染稳定的鲁棒性才行」**
> 本文把它落成可执行、可验收的工程不变量。任何改动若违反其中一条，**优先级高于任何新功能**。

---

## 0. 不变量（Invariants）

### I1 · 打开不得改写
**仅打开一个文档（不做任何编辑）绝不能改变磁盘字节。**
- 允许的**唯一**例外：EOF 空行一次性规范化（±1 字符、**不累积**），且必须在文档中明确登记。
- 应用在打开时不得"顺手修复/规范化"用户的 Markdown；任何规范化都必须是显式操作或用户可见的选择。

### I2 · 往返必须字节等价
`parse(md) → serialize → md'`，要求 **md' == md**（除 I1 的登记例外）。
- 覆盖：frontmatter、BOM、CRLF/LF/混合 EOL、行内 HTML、实体、`ke-*` 标记、代码块、数学、列表嵌套、引用、信息块。
- 正文通道与源码通道都必须满足；导出（KE / 普通 Markdown）也必须满足各自契约。

### I3 · 歧义一律当字面文本（保守解析）
**解析器对"拿不准"的输入必须退化为普通文本，绝不可静默升级为结构节点。**
- 例：孤立 `|` 行**不得**成表（必须"表头行 + 分隔行"才成表）；孤立/未闭合 `$` **不得**吞并后续正文；行首 `-`/`+`/数字`.` 的歧义必须有确定性判定并写进规范。
- 宁可"少识别"（用户看到原文），不可"错识别"（用户内容被重排/吞并）。

### I4 · 回退渲染必须保形
任何渲染回退（公式渲染失败、预算超限、未知节点）都必须**保持正常排版**：
- 不得出现"逐字一行"、宽度塌陷、内容被遮挡；
- 不得把文档可控内容当作 HTML 注入（安全）；
- 回退必须**显式可见**（如提示条），且**不得影响保存内容**。

### I5 · 更新不得追溯改变旧文档
新版本不得让**既存文档**的解析结果/呈现发生变化 —— 除非该变化是修复且经"语料级回归"证明字节与结构不变。
- 新语法若要改变既有语义，必须**版本门控**（`ke_version` 已存在于 frontmatter，可作为开关），旧文档维持旧语义。
- 不允许"用户什么都没做，升级后文档看起来不一样了"。

### I6 · 不静默损坏
任何会导致内容丢失/结构改变的操作，**必须**满足其一：显式确认、可一次撤销、或拒绝执行。
- 反例（已修）：空公式块被写盘后退化为字面 `$$`；源码态正文命令用旧正文覆盖已保存内容；清空公式静默删节点。

## 1. 如何强制（护栏）

| 层 | 手段 | 失败即红 |
|---|---|---|
| **单元/集成** | 每个机制一条「最小复现」用例 + **对照组**（真表格仍成表、无特殊字符仍字节不变） | ✅ |
| **语料级回归** | 把真实语料**副本**作为 fixture，逐篇 `parse → serialize → 逐字节 diff` + 关键节点结构快照 | ✅ |
| **渲染快照** | 对语料关键片段做 DOM 形状断言（节点类型序列 + 关键几何：无"1 字符宽"容器、无逐字换行） | ✅ |
| **发布门禁** | `打开 → 保存 = 字节不变` 作为发版必过项；语料回归 0 漂移才允许发版 | ✅ |
| **运行时可观测** | 打开时做一次"干跑序列化比对"，若与磁盘不一致 → **警告而不覆盖**，并提示可用滚动备份恢复 | 🟡 建议 |

语料来源与使用纪律见 `docs/testing-discipline.md`：**一律用副本在隔离工作区**，绝不打开用户真实工作区。

## 附录 A：导出 PDF 里「根号上横线过长」的完整定案（2026-10-13）

### 结论（已双向验证）
- **这是我们的 bug**：`print.css` 里的后代通配 `overflow: visible !important`（`.ke-editor-prose *` 与 `#root *`）
  把 **KaTeX `.hide-tail` 的裁剪一并覆盖掉** → 打印时把那段 **400em 的 SVG 路径**整条画进 PDF → 上横线远超被开方内容。
- **修复**：两条通配改为 `*:not(.katex):not(.katex *)`（`task-75`，`7b118a2`）。
- **修复前后（主理人真实文档 `Homework-Ch6`，像素级 288dpi 实测）**：
  | | 根号区域最长水平墨迹 |
  |---|---|
  | v1.2.15 导出的 PDF（主理人提供） | **245.88pt**（被开方内容仅 ~33pt）✗ |
  | 修复后同文档导出 | **38.52pt** ✓（√ 字形完整） |

### 测量纪律（**新增硬规定**）
> **禁止把 `page.get_drawings()` 的原始路径长度当作「可见宽度」。**
> PDF 里长路径 + **clip 层级** 是合法表达；`get_drawings()` 默认不套用 clip。
> 判定 PDF 视觉效果必须二选一：
> 1. **像素级**：栅格化（≥200–288dpi）后量「最长连续墨迹」；或
> 2. **clip 感知**：`page.get_drawings(extended=True)` 并检查条目的 `level`/clip 作用域。
> 本轮就是因为违反这条，把一份**正常**的 PDF 误判为「未裁剪」，进而得出「Chromium PDF 不裁剪 SVG」的错误结论。

### 走过的弯路（留档，避免重犯）
| 尝试 | 结果 |
|---|---|
| 注入 `overflow:hidden` / `clip-path:inset(0)` / `contain:paint` / `svg{max-width:100%}` / `svg{width:100%}` | 输出无变化（当时是被误读的"证据"，实际本来就正常） |
| v1「隐藏 `.hide-tail > svg` + 盒内补横线」 | 横线长度对了，但 **√ 字形一起丢失** ✗（√ 就在该 svg 内） |
| v2「收窄 `viewBox` 保留 √」 | 相对原生**变差**：横线 34.25pt → **51.00pt**（宽度比 1.035 → 1.541）✗ |
| **外部独立复核**（2026-10-13 交付） | 用 MuPDF/Poppler 双渲染 + 288dpi 指出：**基线 PDF 本就正确裁剪**，我方量测未考虑 clip → **推翻**了"Chromium 缺陷"结论 ✓ |
| 最终处置 | **回滚 v1/v2 两版 DOM 补丁**，保留 `:not(.katex)` 排除（真修复）；测量口径按上文修正 |

**教训**：把"原始路径长度"当"可见宽度"，导致连续两版错误修法；**外部复核的价值在于推翻，而不是附和**。
