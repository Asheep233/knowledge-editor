# 渲染与往返稳定性（产品级不变量）

> 主理人 2026-10-09 明确要求：**「文档应该有随更新渲染稳定的鲁棒性才行」**
> 本文把它落成可执行、可验收的工程不变量。任何改动若违反其中一条，**优先级高于任何新功能**。

---

## 0. 不变量（Invariants）

### I1 · 打开不得改写
**仅打开一个文档（不做任何编辑）绝不能改变磁盘字节。**
- 允许的**唯一**例外：EOF 空行一次性规范化（±1 字符、**不累积**），且必须在文档中明确登记。
- 应用在打开时不得"顺手修复/规范化"用户的 Markdown；任何规范化都必须是显式操作或用户可见的选择。

### I2 · 往返必须字节等价
`parse(md) → serialize → md'`，要求 **md' == md**（除 I1 的登记例外）。
- 覆盖：frontmatter、BOM、CRLF/LF/混合 EOL、行内 HTML、实体、`ke-*` 标记、代码块、数学、列表嵌套、引用、信息块。
- 正文通道与源码通道都必须满足；导出（KE / 普通 Markdown）也必须满足各自契约。

### I3 · 歧义一律当字面文本（保守解析）
**解析器对"拿不准"的输入必须退化为普通文本，绝不可静默升级为结构节点。**
- 例：孤立 `|` 行**不得**成表（必须"表头行 + 分隔行"才成表）；孤立/未闭合 `$` **不得**吞并后续正文；行首 `-`/`+`/数字`.` 的歧义必须有确定性判定并写进规范。
- 宁可"少识别"（用户看到原文），不可"错识别"（用户内容被重排/吞并）。

### I4 · 回退渲染必须保形
任何渲染回退（公式渲染失败、预算超限、未知节点）都必须**保持正常排版**：
- 不得出现"逐字一行"、宽度塌陷、内容被遮挡；
- 不得把文档可控内容当作 HTML 注入（安全）；
- 回退必须**显式可见**（如提示条），且**不得影响保存内容**。

### I5 · 更新不得追溯改变旧文档
新版本不得让**既存文档**的解析结果/呈现发生变化 —— 除非该变化是修复且经"语料级回归"证明字节与结构不变。
- 新语法若要改变既有语义，必须**版本门控**（`ke_version` 已存在于 frontmatter，可作为开关），旧文档维持旧语义。
- 不允许"用户什么都没做，升级后文档看起来不一样了"。

### I6 · 不静默损坏
任何会导致内容丢失/结构改变的操作，**必须**满足其一：显式确认、可一次撤销、或拒绝执行。
- 反例（已修）：空公式块被写盘后退化为字面 `$$`；源码态正文命令用旧正文覆盖已保存内容；清空公式静默删节点。

## 1. 如何强制（护栏）

| 层 | 手段 | 失败即红 |
|---|---|---|
| **单元/集成** | 每个机制一条「最小复现」用例 + **对照组**（真表格仍成表、无特殊字符仍字节不变） | ✅ |
| **语料级回归** | 把真实语料**副本**作为 fixture，逐篇 `parse → serialize → 逐字节 diff` + 关键节点结构快照 | ✅ |
| **渲染快照** | 对语料关键片段做 DOM 形状断言（节点类型序列 + 关键几何：无"1 字符宽"容器、无逐字换行） | ✅ |
| **发布门禁** | `打开 → 保存 = 字节不变` 作为发版必过项；语料回归 0 漂移才允许发版 | ✅ |
| **运行时可观测** | 打开时做一次"干跑序列化比对"，若与磁盘不一致 → **警告而不覆盖**，并提示可用滚动备份恢复 | 🟡 建议 |

语料来源与使用纪律见 `docs/testing-discipline.md`：**一律用副本在隔离工作区**，绝不打开用户真实工作区。
