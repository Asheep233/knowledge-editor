# KnowledgeEditor 前端 UI · 视觉差别报告

> 对照对象：**设计稿**（`review-pack/design/`，即 `knowledge-editor-ui` 工程） vs **当前实现**（`review-pack/implementation/`）
> 结论方式：实现侧基于真实 GUI 截图目视 + `index.css` / 组件源码核验；设计侧基于 `colors_and_type.css` / `editor.html` / `handoff.md` 源文件（设计基准）。

## 0. 一句话结论

**结构与组件还原度很高**（三栏壳、左栏/右栏/工具栏/正文节点/设置/启动器全部就位，图标为线性风格，正文节点行为符合规格）。**核心视觉差别集中在深色强调色**：设计稿深色主色为「粉红能量色」`#fc2c50`，实现采用「蓝系」`#3b82f6`——这是主理人拍板的**已决差异**（非遗漏）。**且该色值可自由自定义**：应用已实现「自由选择强调色」（浅色/深色各一套，设置页可改），`#3b82f6` 只是出厂默认值，用户可自行改成 `#fc2c50` 或任意色，因此仅代表默认观感差异，不属缺陷。

## 8. 我新发现（超出 README 的观察项，供参考）

1. **「自由选择强调色」已完整实现**：设置页「外观」提供「强调色·浅色」「强调色·深色」两套（色板 + hex 输入 + 重置），`settings.ts` 以 `accentColor.{light,dark}` 持久化，`applyTheme()` 启动/变更时覆写 `--primary`，`index.css` 的 `--primary-hover`/`--secondary` 等派生令牌用 `color-mix` 联动自动跟随。**因此深色默认蓝** **`#3b82f6`** **只是出厂值，用户可在设置页一键改成设计稿的** **`#fc2c50`**，无需改默认代码即可还原深色「能量感」。
2. **强调色并非全链路一致（存在边缘残留蓝调）**：主 CTA 与绝大多数控件走语义 `var(--primary)` 会跟随自定义，但**弹窗主按钮**与**深色** **`--primary-soft`** 是写死的蓝色，不随自定义变化。详见第 10 节。
3. **深色** **`--border`** **为** **`#333333`**，比设计 `#1d1d1c` 亮一档，导致深色卡面分隔线比设计更清晰。可接受，属有意的可辨识取舍。

## 9. 建议（如需进一步贴合）

- **无需改码**：深色强调色默认观感若想对齐设计，用户在设置页「强调色·深色」填入 `#fc2c50` 即可，属于产品已实现的自由选择能力。

- **可选**：统一浅色 `--popover` 为 `#f9f9fa`、深色 `--popover` 为 `#2e2e2e`，让引用块/浮层底色与设计完全一致。

- **可选**：深色 `--border` 调回 `#1d1d1c` 或中间值，弱化分隔线对比。

- **保持**：其余（结构、节点、图标、圆角、单主色纪律、无阴影层级）无需改动。

## 10. 给实现 agent 的修改建议（强调色全链路一致）

> 目标：让「自由选择强调色」在所有场景下都跟随 `--primary`，自定义为粉红 `#fc2c50` 时不再残留蓝色。

**问题根因**：主 CTA（工具栏「导出」）用 `var(--primary)` 遵循自定义；但以下三处**写死了 Tailwind 蓝色**，深色下又被覆盖层固定成蓝，脱离 `--primary`：

### 修改 1：弹窗主按钮改用语义令牌（推荐，跨主题跟随）

三处 `bg-blue-600` → 换成 `bg-primary text-primary-foreground`：

| 文件                                     | 行   | 现状（className）                                                              | 改为                                                                                       |
| -------------------------------------- | --- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `src/App.tsx`                          | 740 | `rounded bg-blue-600 px-3 py-1.5 text-xs text-white hover:bg-blue-700`     | `rounded bg-primary px-3 py-1.5 text-xs text-primary-foreground hover:brightness-95`     |
| `src/App.tsx`                          | 772 | `rounded bg-blue-600 px-2.5 py-1 text-[11px] text-white hover:bg-blue-700` | `rounded bg-primary px-2.5 py-1 text-[11px] text-primary-foreground hover:brightness-95` |
| `src/components/layout/EditorArea.tsx` | 603 | `rounded bg-blue-600 px-3 py-1 text-[11px] text-white hover:bg-blue-700`   | `rounded bg-primary px-3 py-1 text-[11px] text-primary-foreground hover:brightness-95`   |

> 说明：`hover:brightness-95` 与工具栏主按钮使用的效果一致；`bg-primary` 跨浅/深两套主题都映射到 `var(--primary)`，自然跟随自定义。

### 修改 2：深色 `--primary-soft` 改为 color-mix 联动

`src/index.css` 深色块第 506 行：

```css
--primary-soft: rgba(59, 130, 246, 0.16);   /* 现状：写死蓝 */
--primary-soft: color-mix(in srgb, var(--primary) 12%, #ffffff);  /* 改为：跟随 --primary */
```

> 深色下建议按透明度混合（与浅色 `12%` 白不同，深色用 `var(--primary)` 与透明混合更和谐），也可写成 `color-mix(in srgb, var(--primary) 16%, transparent)`，请按深色观感微调。

### 修改 3（可选）：移除深色 `bg-blue-600` 覆盖层（若已不引用）

改完修改 1 后，`src/index.css` 第 586–587 行的深色覆盖层将无对象可用：

```css
[data-theme='dark'] .bg-blue-600 { background-color: #2563eb; }
[data-theme='dark'] .bg-blue-600:hover { background-color: #3b82f6; }
```

可保留（无副作用）或删除。若项目他处仍引用 `bg-blue-600`，建议一并改为 `bg-primary`；反之删除覆盖层避免误导。

### 验收

1. 设置页「强调色·深色」填 `#fc2c50` → 深色页工具栏「导出」、左栏激活态、分段控件、开关、标签徽章、三个弹窗主按钮**全部变粉红**。
2. 任意弹窗主按钮 hover 无蓝色残留。
3. 浅色下强调色改动同样全链路一致（浅色 `--primary`、`--primary-hover`、`--primary-soft` 均由 `color-mix` 派生）。
