- 证据类型：**W（真实产品环境）**

## 实测（marker 均命中，测量有效）

| 文档 | 打开耗时 | 预算 | 结论 |
| --- | --- | --- | --- |
| plain256（256KB 纯文本） | **12,227ms** | <5s | **FAIL** |
| plain512（512KB 纯文本） | **46,460ms** | <8s | **FAIL** |
| formula256（256KB 公式密集） | **11,489ms** | <8s | **FAIL** |
| 启动到主 UI（前次） | 2,162ms | <30s | PASS |
| 小文档（前次） | 328ms | — | PASS |

## 准确归因（修正前两轮）

- **性能瓶颈是文档体积本身，不是公式**：plain256 12.2s ≈ formula256 11.5s（公式没有显著额外开销）；
- 512KB 纯文本 **46.5s**，随体积超线性恶化 → 大文档打开路径（Markdown 解析/序列化/ProseMirror
  doc 构建/属性面板统计等）需要优化；
- 小文档（<2KB）打开 328ms、输入 13ms、guest 启用 57ms 正常；
- 结论：**W09 大文档打开性能 FAIL（真实、可复现、归因清晰）**，需优化后再验证。

## 优化方向（下一步）

1. 剖析打开路径：`markdown → editor doc` 解析、`applyDocTraits/frontmatter`、文档属性/字数统计、
   大纲生成、初始渲染是否重复全量处理；
2. 大文档延迟渲染（分段/虚拟化大纲/禁用非必要初始计算）；
3. 设定并记录 P0 同机基线预算；优化后复跑本探针 + 快速输入/两包/长打印全套 W09。
