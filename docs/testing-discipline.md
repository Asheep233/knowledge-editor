# 真机测试纪律（2026-10-08 事故后定规 · 必须遵守）

## 事故
主理人指出：「**每次修 bug 都会把已有的文档搞乱**」。核查确认：我的真机复验会**打开主理人的真实笔记**，
应用随即**自动保存** —— 只要 Markdown 往返在某个构造上有损，**"只是打开看一眼"就会把文档改坏**。

已确认的第一例（也正是当时在修的 bug）：
`数学分析习题 Week 3 Day 2.md` 第 236 行，列表项内缩进 3 空格的 `$$ … \tag{2.2.2.1} $$`
在 17:20 的自动备份里**还有 tag**，之后文件里 `\tag{2.2.2.1}` **整段消失** —— 与「列表项内 `$$` 被降级为
行内公式 → KaTeX 行内模式不支持 `\tag` → 写回时丢弃」的往返损失吻合（修复见 task-60）。

## 铁律
1. **永远不要在主理人的真实工作区里做会写盘的测试**。所有需要"真的开一个编辑器/真的点一下"的验证，
   一律用**沙箱工作区**（如 `C:\ke-tmp\ke-sandbox`，或临时新建的空 workspace）。
2. 若确实必须打开主理人的文档（例如"必须在原位置量几何"）：**只读测量**，且
   ① 测量前对文件做快照；② 测量后**立即关闭应用**（阻止自动保存）；③ 结束后核对文件 sha 与快照一致，
   不一致就还原并上报。**不要**在测量脚本里点击正文、不要派发按键。
3. **禁止**在真机脚本里对正文派发 `Backspace`/`Enter`/输入类事件 —— 已有两次事故（删掉一个字符、
   误改文档）都源于此。要验键盘行为，用 headless Editor 单测。
4. 每次真机验证结束，回报里必须写：**打开过哪些文件、是否写盘、前后 sha256 是否一致**。

## 排查手段（只读，安全）
- 应用有**滚动自动备份**：`<workspace>/Drafts/backup/<相对路径>/<YYYYMMDD-HHMMSS-mmm>.md`，
  实测覆盖最近 ~20 分钟（每 1–2 分钟一份）。用它做**逐行对照**判断"某个改动是谁造成的"。
- 还有 `Drafts/recovery/*.draft.md`（恢复草稿）与 `.knowledgeeditor/index.db`（索引库，可用于全文搜索）。
- 判断"是不是往返损失"的方法：取备份 A（较早）与当前文件做 `diff`，若差异呈现
  **构造被吞掉/降级**（如 `\tag` 消失、公式变裸文本、段落被拆成逐字一行），基本可判定是往返有损。

## 产品侧硬验收（长期）
**「打开 → 保存」不得改变文件字节**：对每个可疑构造（`\tag`、列表项内缩进 `$$`、行内 HTML、实体、
BOM/CRLF、混排列表…）做"读入 → 立即保存 → 与原文逐字节比对"的用例；不一致即为缺陷，
优先级高于任何 UI 问题（它会**静默改坏用户已有的文档**）。

## 已知的历史症状（观察清单）
- 段落被拆成"每字一行"（`对`/`于`/`整`/`数`）
- 公式退化成裸 LaTeX 文本（如 `b_i}$ … $$S$$，由于$|\mathbb{Z}|=\aleph_0`）
- `\tag{...}` 消失
> 注：前两类在这些文档的**最早备份里就已存在**（非本次探针造成），但同属"往返/编辑通道有损"的表现，
> 未来若在新文档中出现，按缺陷处理。
