## 1. 项① 自定义快捷键（详见 `analysis-1.1.10/shortcuts.md`）

**事实**（带行号证据）
- 可绑定动作：工具栏 **21 项**（全部 `editor.chain()` 直调）+ 应用级 **13 项**（保存/新建/设置/搜索/回收站…，多数已有 `ke-menu:*` 事件桥）；**4 项只能「打开入口」**（链接/图片/表格/脚注/模块选择器）。
- **`doc.next`/`doc.prev` 不存在**（无 Tab 栏、无相邻文档入口）→ 主理人点名要的「切换文档」**需先定义顺序来源**（最近更新顺序？文件树顺序？）。
- **原生菜单确实有加速键**（我最初的 grep 是误判）：`Ctrl+N`/`Ctrl+O`/`Ctrl+,`/`Ctrl+Q`/`Ctrl+R`/`F12` + 预定义编辑项（`menu.rs:40-87`）。窗口消息循环层处理，JS 很可能拦不住 → 应作为**保留键**。
- **既有冲突**：`Ctrl+N` 已双重绑定 —— 原生菜单「新建文档」（`menu.rs:40`）vs 编辑器「插入行内公式」（`editor/index.ts:67-104`）。**做自定义前必须先裁决归属**。
- 设置侧可行，但两个坑：三处同步（`settings.ts` → IPC → `settings.rs` 结构体 + **`from_value_lenient` 白名单** + `sanitize`）；Rust `merge_value` 深合并 → **解绑必须用墓碑值**。既有 28 条设置测试**没有任何一条能发现「三处不同步」** → 需补 2 条守门测试。

**推荐：B 档** —— 设置可配置 + 前端统一 **capture 阶段 keydown 分发器**（先于 ProseMirror 的 DOM handler，能覆盖内置键位与浏览器默认；不必重建编辑器 → 不丢撤销历史/选区；设置即改即生效；纯函数可测）。
Tauri 全局快捷键档**否决**（无 `tauri-plugin-global-shortcut`，且「未聚焦也触发」对编辑器动作语义错误）。

## 2. 项② 公式编辑光标/换行（详见 `analysis-1.1.10/math-cursor.md`）

**现状（探针实测，非推断）**：保存公式**既不设选区也不归还焦点** —— 行内若前态是 NodeSelection，保存后**坍缩到公式「前」一位**；块级 NodeSelection 原地保留（无换行、无 caret）；模态打开时 textarea 抢焦点，关闭后无人归还 → 编辑器失焦。

**改法**：在 `EditorArea` 的 `onSave`/`onDeleteEmpty` **同一事务内**：`setNodeMarkup` →（块级）必要时在 `pos+nodeSize` 插一个 `paragraph` → `setSelection`；事务外 `.focus()`。
- 行内：`setTextSelection(target + node.nodeSize)`（公式后一位）
- 块级：后继是空段落 → 复用；否则显式插段落（**文末不插会 `after+1` 越界抛 RangeError**）；caret 落 `insertPos+1`
- ⚠️ 必须在 **EditorArea 层**发事务（NodeView 是独立 React 根 —— 坑 1 / React #300）
- ⚠️ 实测 **`isEditable=false` 时 PM 命令仍会改文档** → 实现必须加 `ed.isEditable` 闸门（这本身是个既有只读漏洞）
- ⚠️ Esc 退出与「保存」都要覆盖；Tab 已被公式自动补全占用，**不能**设计成按 Tab 跳转

**红线/影响**：`$…$` 与 `$$\n…\n$$` 序列化实测不变；但 ① 块级公式后可能**新增一个空段落**（Markdown 多一个空行）② v1.1.7 设计 §3.2 明写「保存后光标回到文档原型位置」，本项**推翻该决策** → 按规范先行需先改设计文档。

## 3. 项③ 源码模式（详见 `analysis-1.1.10/source-mode.md`）

**核心结论：源码模式保存必须完全绕开 ProseMirror（字符串直存）—— 这是功能定义，不是优化。**
- 生产扩展栈 **41 构造往返实测：逐字节一致 0/41**；语义等价（仅尾换行）19/41；**规范化 22/41**
- 其中 **5 项不可逆丢失**（见 §4）；且**加载期就已改写**（`setKeContent` 内 `normalizeGfmFootnotes`，`editor/index.ts:331`）
- 后端**天然支持直存**：`PUT /api/articles/{id}` 只做 frontmatter 行级合并 + 原子写（`documents.py:259-285`）→ 队列/历史/自写抑制零改动复用；只需新增 4 处「内容来源」分支
- **最大风险不在保存，而在「视图共存」**：切回正文若把源码文本喂 `setKeContent`（内部 normalize + PM），下次正文保存就会规范化用户原文 → MVP 必须「切换前 flush + **单视图排他** + 切回正文一次性提示」
- 两处后端静默行为须写进规范：**删除 frontmatter 键/整块会被 `merge_frontmatter` 静默回填**；正文内未知 ke-* 标记改写则逐字节保留 ✓
- 任务描述里的「正文/模块/导出 视图切换骨架」**不存在**（那是块样式下拉与动作按钮）；可复用点只有 `EditorToolbar.tsx` 的 `tabBar` 插槽（已声明、无调用者），`viewMode` 全仓不存在 → 属**新增状态**

**方案**：MVP = **档 B**（可编辑 + 字符串直存 + 单视图排他 + `<textarea>` 零依赖，6.5–10 人日）；档 A（只读预览，1–1.5 人日）作降级；**档 C（分屏双向同步）不建议**（每次同步都要 serialize/parse，256KB 下 39–138ms / 7–14s，且必经 PM ⇒ 保真必输，15–25 人日）。

**红线：必须规范先行（D 层）** —— `document-format.md` 新增「编辑通道与视图」章节；`markdown-extension-spec.md:30` 的 P2「任何工具不得删除或改写未知 ke-* 标记」需澄清与**用户主动改写权**的边界；补换行（CRLF）策略。

## 4. 顺带发现的既有缺陷（非本轮三项引入，但更该先决策）

### 4.1 保真缺陷 F-1…F-5（**今天就会静默损坏文件**）

| # | 构造 | 实测 输入 → 输出 | 后果 |
|---|---|---|---|
| F-1 | 任务列表 | `- [x] 完成` → `- 完成` | **复选框状态丢失**（生产无 TaskList 扩展，已由 Lead 复核确认） |
| F-2 | 行内 HTML | `正文 <span style="color:red">红</span>` → `正文 红` | **标签被丢** |
| F-3 | HTML 实体 | `&copy;` → `&amp;copy;` | 二次转义 |
| F-4 | BOM + frontmatter | `\ufeff---\r\n…\r\n---\r\n\r\n正文` → `## ---\nke\_version: 1\n\n正文` | frontmatter 整块被当正文（`stripFrontmatter` 正则 `^---` 不识别 BOM，已由 Lead 复核确认），保存时还会再套一层 |
| F-5 | CRLF 全文 | `# 标题\r\n\r\n正文` → `# 标题\n\n正文` | 行尾被统一为 LF（规范未声明换行策略） |
