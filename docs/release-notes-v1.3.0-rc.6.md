# AstraNota v1.3.0-rc.6（Release Candidate 6）

> **发布候选版**：正式版仍为 `v1.2.18`（Latest）。RC.6 修复用户实测的**关窗卡死 + 未保存提示无法解决**问题：
> 一直提示「有 2 篇文档未保存成功」，点「确定」后不退出、不显示是哪几篇。

## 根因（三个叠加）

1. **保存队列的失败条目永不重试**：文档在外部被删除/改名后，保存会持续 404；`saveQueue` 把条目记为 `failed` 后保留，但 `flushPending/All` 只处理「有未落盘新内容」的条目，**不会重试失败条目** → 这两篇永远算「未保存」，关窗永远提示，且用户无法通过正常编辑修复（文件已不存在）。
2. **首次关窗立即隐藏窗口**：确认框在**隐藏窗口**里弹出，用户看不到；从任务栏重新唤起又会触发单实例 `cancel_pending_exit` 复位握手 → 再次关窗又隐藏 → 形成「一直提示、点确定不退出、窗口消失」的循环。
3. **确认退出依赖隐藏窗口的二次 CloseRequested**：隐藏窗口上的 `Window.close()` 在 WebView2/该环境下未生效（实测点确定后主窗口隐藏、进程与侧车持续存活数天），没有真正进入退出清理。

## 修复

- **保存队列**（`state/saveQueue.ts`）：
  - 失败条目保留**失败时的保存函数**，`flushPending`/`flushPendingAll`（关窗/重载前会调用）**自动重试一次**；成功即清除未保存状态，重试仍失败才继续拦截并提示。
  - 新增 `unsafeDocs()`：返回「文档 id + 人类可读标题」，用于提示框。
  - `enqueueSave` 支持传入文档标题（EditorArea 保存时带上当前文档标题）。
- **关窗流程**（`desktop/src-tauri/src/lib.rs` + `frontend/src/desktop.ts`）：
  - 首次关窗**不再隐藏窗口**，确认框在正常可见窗口内弹出；
  - 前端收到 `ke:close-requested` 后**立即**取消 Rust 的 1.5s 兜底强退，再全速 flush（含上述自动重试）；
  - 提示文案改为明确列出**哪几篇**文档：`有 N 篇文档未保存成功：<标题>、<标题>…。立即退出将丢失这些修改。仍要退出？`（超过 5 篇显示「等 N 篇」）；
  - 用户点「确定」后调用**新增 Rust 命令 `app_force_exit`**：直接走有界退出清理（结束 sidecar + 8s 硬超时 watchdog），不再依赖隐藏窗口的二次关窗事件；点「取消」则 `app_cancel_pending_exit` 复位握手，窗口保持可见。
  - 重载（Ctrl+R）同样：立即取消兜底 → flush/重试 → 失败时列出标题确认 → 执行重载。
