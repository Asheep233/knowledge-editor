# AstraNota v1.3.0-rc.4（Release Candidate 4）

> **发布候选版**：正式版仍为 `v1.2.18`（Latest）。RC.4 修复两个 **Markdown 往返格式崩坏**问题（用户实测「重开页面后粗体变字面 `**`、空行变 `&nbsp;`」），并让旧文档在打开时自愈。

## 修复 1：空行被序列化成 `&nbsp;` 并显示为字面实体

**根因**：上游 `@tiptap/extension-paragraph` 为了保留连续空行，会把第 2 个及之后的空段落序列化成 `&nbsp;`；本仓库的「HTML 实体保真」tokenizer（F3-8 严格往返）会先把 `&nbsp;` 认领成行内 HTML 原子，导致上游「单 token `&nbsp;` → 空段落」的特判永远不命中 → 空行显示成字面 `&nbsp;` 芯片，再被原样写回文件，形成稳定污染。

**修复（`editor/extensions/KeParagraph.ts`）**：
- 接管 `Paragraph.parseMarkdown`：单 token 且为 `&nbsp;` / NBSP / `&#160;` 的段落 → 还原为空段落；
- **旧文档自愈**：打开含 `&nbsp;` 空行的文档时自动还原成空行（不是字面文本），保存后按上游规范写回连续空行标记；
- 混合行（如 `&copy; &nbsp;`）token 数 >1，仍保持原字节，F3-8 严格往返不回归。

## 修复 2：粗体/斜体/删除线以标点结尾并紧邻文字时变成字面 `**`

**根因**：序列化器输出 CommonMark **非法强调**。典型：粗体文本 `正常字体。` 后紧跟文字 `继续` → 输出 `**正常字体。**继续`；闭合 `**` 前是标点、后是词字符，不满足 right-flanking → 下次解析回退成字面 `**` 文本；再保存时 `*` 被转义成 `\*\*`，永久稳定。同类还有「标记以标点开头、前面紧邻词字符」。

**修复**：
- **序列化期（`editor/markdown-boundary.ts`）**：序列化前规范化 JSON，把会导致非法边界的一侧标点移出标记范围（标点保留为普通文本，文字不丢；只是标点不再加粗/斜体/删除线）。输出始终是合法 Markdown，且幂等；对合法文档零行为变化。
- **加载期（`editor/emphasis-repair.ts`）**：旧版本已写坏的文件在打开时会自动把「边界非法的强调对」改写为等价 HTML 标签（`<strong>`/`<em>`/`<s>`）再解析 → 粗体恢复；保存时自动写回合法 Markdown，**旧文档自愈**。
- 安全边界：跳过围栏代码块、行内代码、反斜杠转义；只处理成对且边界非法的分隔符；孤立 `*` 保持原文。
